# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

`task sanity` (fmt → vet → lint → test) is the gate for every change; build and docker tasks depend
on it. Run it instead of the individual `go` commands.

```sh
task sanity                            # go fmt, go vet, golangci-lint --fix, go test -race -cover ./...
task go-build-app                      # sanity, then ./dist/app/stratus
task go-build-cli                      # sanity, then ./dist/cli/stratuscli
task go-build-cli-dist                 # cross-built CLI binaries (linux amd64/arm64, darwin arm64)
task buf-gen                           # regenerate api/grpc from proto/
task docker-run                        # build the image and start compose.local.yaml
task docker-run-cli -- info            # CLI in a container; args after `--` go to stratuscli
```

Tests are testify suites, so a single case is addressed as `SuiteEntryPoint/MethodName`:

```sh
CGO_ENABLED=1 go test -race -run 'TestStorageSuite/TestReadStillCapped' ./internal/storage/
```

`-race` needs cgo, and the Taskfile sets `CGO_ENABLED=1` for tests because the rest of the build
runs with it off.

Run the server with `WAL_DIR` set — it is the one required setting. Every config field is both a
flag and an uppercased env var (`--dedup_window` / `DEDUP_WINDOW`); `auth_token` is env-only.

## Architecture

A single gRPC service (`stratus.v1.StreamService`) over an append-only WAL, layered strictly:

```
cmd/app/server   gRPC handlers: proto <-> internal types, timeout clamping, error -> status code
internal/stream  LRU cache + WAL orchestration, live-tail fan-out (the `Stream` the server sees)
internal/storage WAL wrapper: range validation/clamping, dedup on write, follower subscriptions
internal/dedup   time-windowed dedup-key set
```

`cmd/app/stratus.go` wires them bottom-up (wal → storage+dedup → stream+lru → grpc server) and runs
three errgroup goroutines: signal handling, `stream.Start`, and `grpc.Serve`. `stream.Start` preloads
the cache from the WAL range, then blocks forever consuming a `storage.Subscribe` follower channel,
putting each new record into the LRU and firing `notify()`. Startup waits on `WaitForStart` before
serving, so the cache is warm before the first RPC.

Reads go through the cache: `Stream.Get` clamps the range in storage, then `lazyLoadRecord` serves
each ID from the LRU and falls back to a single-record WAL read (caching the result) on a miss.
`ReadOffset` is the live tail — the handler drains what exists and then waits on `Stream.DataReady()`
(the channel `notify()` closes and replaces) for more.

Boundary rules, so they stay in one place:

- Range validation and clamping live in `internal/storage` (`validateRange`, `checkRange`,
  `ClampRange`) — never in the stream/cache layer.
- Errors are sentinel values per package (`storage.ErrOutOfBounds`, `stream.ErrAllSkipped`, …) and
  are mapped to gRPC codes exactly once, in `server.toStatus`.
- The `Server` depends on a local `Stream` interface, not on `*stream.Stream`.
- `Delete` = `wal.TruncateContext` + `wal.CutOffsetContext`, so removal is exact; `Stream.Del` then
  evicts the deleted IDs from the LRU.

`api/grpc/` is generated by buf from `proto/stratus/v1/stratus.proto` — edit the proto and run
`task buf-gen`, never the generated files. `pkg/stratusv1` is the hand-written Go client: it has its
own DTOs (`dto.go`) so callers never import the protobuf package, which means a proto change usually
needs a matching DTO/conversion change there.

`cmd/cli` is a cobra CLI (one command per RPC) plus a bubbletea TUI (`--tui`) in `cmd/cli/tui`.

Known gap: `config.MaxBatchReadSize` (`max_batch_read_size`) is parsed but never wired into storage,
which keeps `defaultReadBatchSize = 64`.

## Conventions

- Go functions returning three or more values use named return values.
- Tests use `testify/suite` with table-driven cases and `actual`/`expected` naming.
- Durations cross the API as `google.protobuf.Duration` (`durationpb`) and `time.Duration` in the
  client DTOs — never a bare nanosecond integer.
- Dependencies are constructor options (`storage.WithWAL`, `stream.WithCache`, …), validated in `New`.
- `golangci-lint` runs with `--fix` and enables `funlen`, `gocyclo`, `dupl`, `lll`, `gosec` among
  others — keep functions under 100 lines and lines under 150 chars.
